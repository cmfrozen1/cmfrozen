## 5. ฐานข้อมูล — ต้องทำอะไรไหม?

**ไม่ต้องรันอะไรกับ DB เพื่อให้ฟีเจอร์ใหม่ทำงาน** ระบบจัดการให้เอง:

- คอลัมน์ใหม่ `shipping_carrier` (VARCHAR 128, NULL) ในตาราง `orders` จะถูกเพิ่ม **อัตโนมัติครั้งเดียว**
  โดย `ensureOrderTrackingColumn()` ใน api.php — เช็คก่อนว่ายังไม่มีคอลัมน์จึงจะ ADD (idempotent)
  ข้อมูลออเดอร์เดิมทุกแถวไม่ถูกแตะ (คอลัมน์ใหม่เป็น NULL จนกว่าจะกรอกจริง)
- ไฟล์ `initdatabase.sql` ถูกแก้ให้ปลอดภัยแล้ว: ทุก INSERT ใช้ `ON DUPLICATE KEY UPDATE id = id`
  → รันซ้ำกี่ครั้งก็ได้ จะเติมเฉพาะแถวที่ **ยังไม่มี** เนื้อหาเดิมที่แก้ไว้ทางหน้า Admin จะ **ไม่ถูกเขียนทับ**
- `seedDbFromData()` ใน api.php ก็แก้เป็น additive แล้ว และทำงานเฉพาะตอนตาราง `site_sections` ว่างเปล่าเท่านั้น

### ถ้าอยากใช้ข้อความ rebrand ใหม่ ("Fukupetstore Club" ฯลฯ) บนเว็บ
เนื้อหาใน DB จะมาก่อนค่า default เรื่อย ๆ มี 2 ทางเลือก:
- **ทางที่ง่าย (แนะนำ):** เข้า `admin.html` → แก้ข้อความส่วนที่ต้องการ (เช่น หัวข้อ Club, About, Copyright) → กดบันทึก
- **ทางที่เปลี่ยนทั้งหมด:** กดปุ่ม "Run Init DB" ในหน้า Admin หลังอัปโหลด — ปลอดภัยแล้วเพราะสคริปต์ additive-only
  (แถวที่มีอยู่จะไม่ถูกแตะ แถวใหม่เช่น section ที่เพิ่มเติมจะถูกเติมให้)

## 7. สำรอง/ย้อนกลับ (Rollback)

- ไฟล์เดิมจากเซิร์ฟเวอร์ถูกเก็บไว้ที่ `backup_server/` (จากสคริปต์ .bat หรือขั้น 4.2 ที่ลากไว้)
- ถ้าอยากย้อน: อัปโหลดไฟล์ใน `backup_server/` กลับขึ้นเซิร์ฟเวอร์ทับอีกครั้ง = กลับสู่สถานะเดิม
- ฐานข้อมูลไม่ถูกลบ/แก้ไขสิ่งที่มีอยู่ จึงไม่ต้อง restore DB
